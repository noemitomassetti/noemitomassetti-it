2. Guida utente: originale inglese e proposta italiana

La funzione descritta è predisposta per l'esempio per questa simulazione; non sono state configurate piattaforme né verificati permessi di accesso reali.

Original EN — Step 3: Assign roles and enable just-in-time provisioning

After configuring a SAML 2.0-compatible identity provider (IdP), enable the option labelled “Automatically provision users”. Team members who sign in using the verified company domain will receive the default Member role, unless a different role-mapping rule has been configured in the security settings. Review the assigned role before granting access to shared projects.

Traduzione IT — Passaggio 3: assegnazione dei ruoli e creazione automatica degli utenti

Dopo aver configurato un provider di identità (IdP) compatibile con SAML 2.0, attiva l'opzione «Crea automaticamente gli utenti». I collaboratori che accedono con il dominio aziendale verificato ricevono il ruolo predefinito di Membro, salvo diversa regola di assegnazione definita nelle impostazioni di sicurezza. Controlla il ruolo assegnato prima di autorizzare l'accesso ai progetti condivisi.

3. Controlli editoriali dell'estratto

  • Conservati i riferimenti tecnici a IdP e SAML 2.0.
  • La procedura non presuppone di aver testato il prodotto o configurato un account reale.
  • Le etichette di interfaccia devono corrispondere ai nomi effettivi delle funzioni prima di essere utilizzate nella documentazione di un software.

5. Guida utente bilingue: percorso completo di prova

English · Original instructions

Before you begin. Make sure that you have been assigned a role with the appropriate permissions. The names shown below refer to an illustrative interface and may not match the labels of any real software.

Step 1 — Open the workspace. Sign in using the access method provided by your organisation. Choose the workspace you have been authorised to use. If you cannot see it, do not request another user's credentials; contact the administrator.

Step 2 — Review folder access. Open the folder list and check the access indicator beside each project. Users with the Member role can see only the folders enabled for them. If you need additional access, submit a request to the administrator rather than changing permission settings yourself.

Step 3 — Upload a document. Select the destination folder, choose Upload and select the relevant file. Wait for the confirmation message before closing the window. If the connection is interrupted, check whether the file is already present before trying again.

Step 4 — Check the version. Open the file details and compare the name, date and version label with the approved project register. Avoid replacing an approved file with an unreviewed draft.

Step 5 — Request approval. Choose the authorised reviewer and send the review request only if you have permission to do so. Do not treat the document as approved until that reviewer has confirmed the decision.

Italiano · Traduzione e localizzazione

Prima di iniziare. Verifica che ti sia stato assegnato un ruolo con i permessi necessari. I nomi delle funzioni citate di seguito appartengono a un'interfaccia immaginaria e potrebbero non corrispondere a quelli di alcun software reale.

Passaggio 1 — Apri lo spazio di lavoro. Accedi con la modalità prevista dalla tua organizzazione. Seleziona lo spazio di lavoro per cui hai ricevuto l'autorizzazione. Se non lo trovi, non chiedere le credenziali di un'altra persona: contatta l'amministratore.

Passaggio 2 — Controlla l'accesso alle cartelle. Apri l'elenco delle cartelle e verifica l'indicazione dei permessi accanto a ciascun progetto. Gli utenti con ruolo Membro vedono soltanto le cartelle abilitate. Se hai bisogno di ulteriori autorizzazioni, invia una richiesta all'amministratore senza modificare autonomamente le impostazioni.

Passaggio 3 — Carica un documento. Seleziona la cartella di destinazione, scegli «Carica» e indica il file pertinente. Prima di chiudere la finestra, attendi il messaggio di conferma. Se la connessione si interrompe, verifica se il file è già presente prima di ripetere l'operazione.

Passaggio 4 — Controlla la versione. Apri i dettagli del file e confronta nome, data e versione con il registro del progetto approvato. Evita di sostituire un documento approvato con una bozza non revisionata.

Passaggio 5 — Richiedi l'approvazione. Seleziona la persona autorizzata alla revisione e invia la richiesta soltanto se disponi dei permessi previsti. Il documento non deve essere considerato approvato finché il revisore non ha confermato la decisione.

4. Guida utente completa: gestione delle richieste di accesso

Scenario: «CloudSync Enterprise» è un'applicazione dimostrativa. Le istruzioni sono un esercizio di localizzazione della documentazione; non sono state verificate su un software reale e non devono essere eseguite come procedura di sicurezza.

Source guide · English (UK)

Before you begin. Ask the account administrator to confirm which team members need access to a shared project. Make sure that the identity provider and the list of available roles have already been configured by the authorised technical team. Do not request passwords from other users.

Step 1 — Review the request. Open the access-request list and select the entry you need to examine. Check the project name, the requested role and the reason for access. If any information is missing, mark the request as pending clarification rather than approving it.

Step 2 — Check the proposed permissions. Compare the requested role with the permissions described in the administrator's approved role matrix. A project editor may be able to modify shared files, while a viewer may only read them. Do not treat this example as a complete security policy.

Step 3 — Submit for approval. When the request is complete, send it to the authorised administrator for review. The request remains pending until the administrator has approved or declined it. Preparing a request is not the same as granting access.

Step 4 — Read the confirmation. If the system reports that the approval has been recorded, check that the request identifier and project name are correct. If the status remains pending, do not tell the user that access has been granted.

Step 5 — Resolve an error. If the request cannot be saved, keep the displayed error message and the request identifier. Try again only when the approved procedure allows it; otherwise contact the authorised support contact. Never include passwords or security tokens in a support email.

After the request. Record the outcome in the activity log and retain only the information needed for the agreed operational purpose. Where applicable, the technical team should review access permissions periodically.

Guida localizzata · Italiano

Prima di iniziare. Chiedi all'amministratore dell'account di confermare quali collaboratori devono accedere al progetto condiviso. Verifica che il provider di identità e l'elenco dei ruoli siano già stati configurati dal personale tecnico autorizzato. Non richiedere le password degli altri utenti.

Passaggio 1 — Esamina la richiesta. Apri l'elenco delle richieste di accesso e seleziona quella da verificare. Controlla il nome del progetto, il ruolo richiesto e la motivazione. Se mancano informazioni, imposta lo stato «In attesa di chiarimenti», senza approvare la richiesta.

Passaggio 2 — Verifica i permessi proposti. Confronta il ruolo richiesto con quelli indicati nella matrice di autorizzazioni approvata dall'amministratore. Un collaboratore con ruolo di modifica potrebbe intervenire sui file condivisi, mentre chi dispone di permessi di sola lettura può consultarli. Questo esempio non sostituisce una procedura di sicurezza completa.

Passaggio 3 — Richiedi l'approvazione. Quando la richiesta è completa, inoltrala all'amministratore autorizzato. Lo stato rimane «In attesa» finché il responsabile non l'approva o la rifiuta. Preparare una richiesta non equivale a concedere un accesso.

Passaggio 4 — Controlla la conferma. Se il sistema segnala che l'approvazione è stata registrata, verifica il codice della richiesta e il nome del progetto. Se lo stato è ancora «In attesa», non comunicare all'utente che l'accesso è stato autorizzato.

Passaggio 5 — Gestisci un errore. Se non è possibile salvare la richiesta, annota il messaggio di errore visualizzato e il relativo codice. Ripeti l'operazione soltanto se previsto dalla procedura approvata; in caso contrario contatta l'assistenza autorizzata. Non inserire password o codici di sicurezza nei messaggi di supporto.

Dopo la richiesta. Registra l'esito nel registro attività e conserva soltanto le informazioni necessarie allo scopo operativo concordato. Dove previsto, il personale tecnico dovrà riesaminare periodicamente le autorizzazioni di accesso.
